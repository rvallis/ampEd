## 🧠 THE WHAT

# CHAT TALKS. CODE ACTS.

Four words. Claude Chat gives you advice and text you copy yourself. Claude Code reads your files and actually runs the changes, directly, without you doing the copying.

### The One-Sentence Version

> Chat is Claude with a voice, Code is Claude with hands, and the difference matters more than it sounds like it should.

### The Core Idea

In a regular Claude Chat conversation, you might ask for a script, get one back, and then have to copy it, open your own terminal, paste it in, and run it yourself. Claude gave you the words, you did the doing.

Claude Code changes that relationship. It runs on your actual computer, can read your real files, and can execute commands directly, no copy-paste step required. It isn't just Claude Chat squeezed into a terminal window, it's a fundamentally different interaction: instead of describing what to do, Claude actually does it, then shows you the result.

**Analogy:** Chat is like calling a smart friend for advice, they'll explain something clearly or write something out for you to use yourself. Code is like handing that same friend your actual keyboard and saying "just do it," and watching them make the change directly.

### The Practical Difference

| | Claude Chat | Claude Code |
|---|---|---|
| **What it can touch** | Nothing directly, gives you text to copy | Your real files, directly |
| **How work gets done** | You paste its output somewhere yourself | It runs commands and edits files itself |
| **Best for** | Thinking through an idea, learning, brainstorming | Actually building or automating something |

### Quick Check

You want Claude to explain the difference between two grading approaches so you can decide which to use. Chat or Code?

<details>
<summary><strong>See a strong answer</strong></summary>

> Chat. This is thinking and deciding, not doing. There's no file to touch and nothing to execute, you just want a clear explanation to inform a decision you'll make yourself. Code becomes the right tool once you've decided and want something actually built or automated, like a script that applies your chosen grading approach automatically.

The test is simple: are you trying to think something through, or are you trying to get something actually done on your computer? The first is Chat. The second is Code.

## 🔄 THE HOW

---

### "Thinking It Through vs. Actually Building It"
**For anyone deciding which tool fits a given task**

Someone weighing whether to automate part of their weekly workflow used Chat first, talking through the idea, asking questions, deciding what the automation should actually do. Once the plan was clear, she switched to Code to actually build it, have it read the relevant files, and run the automation for real. Chat helped her think. Code helped her build.

**Neither tool replaced the other. Each did the half of the job it was actually built for.**

*Research note: this distinction, Chat as conversational advice you act on yourself versus Code as an agent that reads your files and executes changes directly, is a well-documented and often-repeated observation from people learning the difference themselves. One description puts it simply: Code isn't Chat with a terminal attached, it's Chat with hands.*

---

### "Realizing She'd Been Doing the Copy-Paste Herself"
**For anyone new to automation who's been doing manual work by hand**

Someone building her first small automation had been asking Chat for scripts, then manually copying them into her own terminal and running them, one small step at a time, unaware there was a faster path. Once she tried Claude Code and saw it read her actual files and run the script directly, without her doing the copying, she realized how much manual work she'd been doing that didn't need to be manual at all.

**The capability wasn't new. She just hadn't known the tool that removes the copy-paste step existed.**

---

### "Knowing Which One to Reach For, By Instinct"
**For anyone directing both conversations and real project work**

A veteran teacher who now directs both conceptual planning and real technical builds describes it simply: if she's still figuring out what she wants, she's in Chat. Once she knows exactly what needs to get built, she moves to Code and lets it actually do the work. The switch itself, recognizing which mode a moment calls for, becomes second nature with practice.

**The skill isn't using either tool well in isolation. It's knowing, in the moment, which one the task actually calls for.**
