## 🧠 THE WHAT

# TEACH IT ONCE. USE IT FOREVER.

Six words. A Skill is a saved, reusable set of instructions, written once, that Claude can load and follow every time a matching task comes up, so you never retype the same brief again.

### The One-Sentence Version

> If you've ever pasted the same long instructions into a Claude conversation more than a couple of times, that's exactly the task a Skill was built to absorb.

### The Core Idea

A lot of real work is the same job, done slightly differently, over and over: writing release notes, drafting a certain kind of report, formatting data a specific way. The typical approach without Skills is pasting the same detailed instructions into a fresh conversation every time, tweaking as needed, and repeating the whole thing next week.

A Skill fixes this. You write the process once, save it, and Claude can load and run it consistently whenever the matching task comes up, without you re-explaining it from scratch. A commonly cited rule of thumb: if you find yourself repeating the same long prompt roughly three times a week, that's the signal it's worth turning into a Skill.

**Analogy:** think of the difference between explaining a recipe to someone from memory every single time you cook together, versus writing it down once and just saying "let's make the usual" going forward. The recipe doesn't change. What changes is whether you have to re-explain it every time.

### When a Skill Is Worth Building

| Signal | Not quite a Skill yet |
|---|---|
| You've done the same task the same way three or more times | It's a genuine one-off, unlikely to repeat |
| The steps are consistent and repeatable | The task is highly conversational or unpredictable each time |
| You keep a doc of prompts you copy-paste from | You've only ever written the instruction once |

### Quick Check

You've written a detailed prompt for summarizing client meeting notes into action items, and you've now used that same prompt, tweaked slightly, four separate times this month. Is this a Skill candidate?

<details>
<summary><strong>See a strong answer</strong></summary>

> Yes, this is a textbook Skill candidate. A consistent, repeatable process, used multiple times with the same underlying structure, is exactly what a Skill is meant to absorb. Building it once as a Skill means the fifth time you need it, you invoke it with a short request instead of retyping or hunting down the prompt you used last time.

The clearest signal is repetition with a consistent structure. If the task changes wildly every time, a Skill won't help much. If it's basically the same job with small variations, it will.

</details>

## 🔄 THE HOW

---

### "Retiring the Google Doc Full of Prompts"
**For anyone who's built up a personal library of copy-paste instructions**

Someone who'd spent months accumulating a document full of carefully worded prompts for recurring tasks, one for weekly reports, one for a specific kind of summary, realized she was spending real time each week just finding and pasting the right one in. Turning her most-used prompts into Skills meant she could invoke them with a short, natural request instead, and the document of prompts she used to maintain became unnecessary.

**The instructions themselves hadn't gotten better. She'd just stopped needing to go find and paste them every single time.**

*Research note: this exact pattern, a growing personal document of copy-pasted prompts becoming unnecessary once the same instructions are saved as reusable Skills, is described directly by people who've adopted the practice, not a hypothetical benefit.*

---

### "Building the First One From an Honest Count"
**For anyone deciding whether a task is worth turning into a Skill**

Someone considering whether to build her first Skill used a simple test: had she genuinely written this exact kind of instruction three or more times in the same month? For one task, drafting a specific kind of client update, the honest answer was yes, five times. That became her first Skill. A different task she'd only done once stayed a regular prompt, since there was no real repetition yet to justify the setup.

**The decision wasn't "would a Skill be nice." It was an honest count of how often she was already repeating herself.**
